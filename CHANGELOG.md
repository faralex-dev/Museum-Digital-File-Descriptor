# История изменений

## Не выпущено

- В описание аудио и видео записываются теги из самого файла: название,
  исполнитель, композитор, альбом, номер дорожки, жанр, комментарий, авторские права.
- Для RAW-файлов, которые не открывает Pillow (например, Sony ARW), EXIF
  читается напрямую: камера, объектив, выдержка, диафрагма, ISO, дата съёмки.
  Для остальных изображений тоже добавлены объектив и параметры съёмки.
- Эти сведения попадают и в памятку для КАМИС.
- Название камеры без повтора производителя: «Canon EOS 6D» вместо
  «Canon Canon EOS 6D».
- Служебные предупреждения Pillow о нестандартных тегах (IPTC в TIFF) больше
  не выводятся в командной строке.
- Служебные названия дорожек («Core Media Video», «SoundHandler» и т. п.)
  не записываются.
- Обновление описаний версии 1.x: если в папке есть описание 1.x, программа
  сверяет файлы с его контрольными суммами, переносит файлы 1.x в подпапку
  «_описание 1.x» и создаёт описание 2.0. Раньше предмет пропускался как «уже
  описанный», если XML 1.x назывался так же, как новый. Если суммы не сходятся
  или описание 1.x относится к другому файлу, ничего не меняется и выводится причина.

## 2.0.3 — 2026-09-21

- Исправлено: в окне программы (приложение для macOS, запущенное из Finder)
  MediaInfo по-прежнему не открывал видео и аудио с русскими буквами в пути —
  окно Tk при создании сбрасывало настройку кодировки, сделанную в 2.0.2.
  Теперь она восстанавливается перед каждым чтением файла, а сборка
  проверяется и в сценарии с окном.

## 2.0.2 — 2026-09-21

Правки по описанию видеофайлов.

- Исправлено: приложение для macOS, запущенное из Finder, не получало сведений
  о видео и аудио, если в пути к файлу есть русские буквы (MediaInfo не открывал
  файл). Сверка по той же причине могла ошибочно считать такие файлы
  неоткрывающимися.
- Под таблицами результатов — поле «Подробности»: длинное сообщение выбранной
  строки видно целиком.
- В предупреждениях больше нет полного пути к файлу.
- Сверка описания одного файла («видео.mp4.checksums.txt») больше не считает
  «лишними» соседние файлы и подпапки.
- Язык дорожки подписан как «Язык (метка в файле)»: камеры записывают его сами
  (часто «английский»), к языку речи он может не относиться.

## 2.0.1 — 2026-09-21

Правки по первому описанию реального предмета (ЦНАР_102, 106 файлов PNG, 6,5 ГБ).

- Файлы в описании идут в естественном порядке: 1, 2, 3 … 10, а не 1, 10, 100, 2.
- Предупреждение о файлах с одинаковым содержимым внутри предмета
  (например, конфликтные копии синхронизации «файл (2).png»).
- Предупреждение, если в учётном номере нет цифр: вероятно, разделитель
  разрезал номер (так было с папкой «ЦНАР_102»).

## 2.0.0 — 2026-09-18

Программа переписана. Формат описания изменён — см. [docs/format-2.0.md](docs/format-2.0.md).

### Новое
- Единица хранения по разделу XXXIII Единых правил (приказ Минкультуры № 827): один предмет — одна папка, в ней
  мастер-копии (можно несколько, можно в подпапках), XML и файл контрольных сумм.
- Три режима: папка — один предмет; каждая подпапка — отдельный предмет;
  каждый файл — отдельный предмет.
- Сведения о предмете: учётный номер (по умолчанию из имени папки до «_»),
  наименование, описание, топография, носитель, сведения о нормализации.
- Контрольные суммы SHA-1 (как в КАМИС) и ГОСТ 34.11-2018 за один проход по файлу.
  SHA-256 в новых описаниях не используется, но при сверке распознаётся.
- **Сверка** (пп. 33.5–33.8): пересчёт сумм, проверка открытия файлов,
  поиск отсутствующих и лишних файлов, проверка резервной копии, отчёт
  (текст или CSV) и дата для поля «Сверка» в КАМИС. Понимает описания версии 1.x.
- Идентификаторы форматов PRONOM и замечания о пригодности формата для
  длительного хранения (п. 33.10).
- Сводная таблица CSV для КАМИС по всем описанным предметам.
- Версия программы и формата записывается в XML.
- Командная строка: `mdfd describe`, `mdfd verify`, `mdfd info`.
- Разделитель учётного номера в имени папки настраивается (по умолчанию «_»).
- Всплывающие подсказки к режимам, полям и кнопкам.
- Тесты, сборка для Windows и macOS через GitHub Actions.

### Меньше внешних зависимостей
- Хеш ГОСТ — собственная реализация на C внутри программы (сверена с
  контрольными примерами стандарта и с pystribog); сборка pystribog и
  Microsoft C++ Build Tools больше не нужны.
- ImageMagick заменён на Pillow; MediaInfo входит в пакет pymediainfo.
- Кодировка текста определяется без chardet, DOCX/ODT/RTF разбираются без
  python-docx, odfpy и striprtf; ttkthemes и tqdm больше не нужны.

### Исправлено
- Все ошибки из [обзора кода 1.x](docs/review-1.x.md), в том числе затирание
  исходного `.txt` и совпадение имён описаний.
- Окно не зависает при обработке больших файлов, работу можно отменить.
- Перезапись существующего описания отменяется, если файлы мастер-копии
  изменились с прошлого раза.
- Сложные случаи (tests/test_edge_cases.py):
  - управляющие символы (из Word, из метаданных камер) больше не делают XML нечитаемым;
  - имена файлов записываются в Unicode NFC — описание, сделанное на macOS,
    сверяется на Windows и Linux, и наоборот;
  - вложенная папка со своим описанием не попадает в описание родительской папки;
  - символические ссылки пропускаются с предупреждением;
  - имена с переводом строки отклоняются с понятным сообщением;
  - файлы описания записываются «всё или ничего»: при сбое не остаётся XML
    без файла контрольных сумм и временных файлов;
  - если файл изменился во время чтения (ещё копируется), описание не создаётся;
  - понятные сообщения при отсутствии прав на чтение файла или запись в папку;
  - повреждённые даты файлов не останавливают работу;
  - при сверке пути вида `../` и абсолютные пути в файле контрольных сумм
    отклоняются; файл, пересохранённый в Блокноте (ANSI, CRLF, BOM), читается.
