# Формат описания 2.0

Программа создаёт для каждого цифрового музейного предмета (ЦМП) единицу
хранения по пп. 33.11–33.16 [Единых правил](https://base.garant.ru/74868877/)
(приказ Минкультуры России от 23.07.2020 № 827):

| Файл | Назначение |
|---|---|
| файлы мастер-копии | сам предмет (один или несколько файлов, можно в подпапках) |
| `<основа>.xml` | файл метаданных, UTF-8: и административные (п. 33.13), и описательные (п. 33.14) сведения в одном файле |
| `<основа>.checksums.txt` | файл контрольных сумм мастер-копии и файла метаданных (п. 33.15) |
| `<основа>.kamis.txt` | памятка для заполнения КАМИС — **вспомогательный** файл, в единицу хранения не входит, можно не создавать |

**Основа имени** зависит от режима:

* «Папка — один предмет» и «Каждая подпапка — отдельный предмет»: имя папки
  предмета, например `ГМИГ КП ЭФ-55_Петров А.А._Соловки.xml`;
* «Каждый файл — отдельный предмет» и описание одного файла: полное имя файла
  **вместе с расширением**, например `фото.jpg.xml`, `фото.jpg.checksums.txt`.
  Поэтому `фото.jpg` и `фото.tif` в одной папке не мешают друг другу, а
  описание `заметки.txt` никогда не затрёт сам документ.

Учётный номер по умолчанию — часть имени папки (файла) до первого знака «_»
(так принято во внутримузейных правилах): `ГМИГ КП ЭФ-55_Петров А.А._Соловки` → номер `ГМИГ КП ЭФ-55`,
классификатор `Петров А.А._Соловки`.

## Файл метаданных (XML)

Кодировка UTF-8. Имена элементов — латиницей (удобно для машинной обработки),
у каждого элемента есть атрибут `label` с подписью по-русски (удобно читать).
Пустые необязательные поля не записываются.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<DigitalMuseumItem formatVersion="2.0">
  <Generator label="Программа" version="2.0.0" hashBackend="C"
             pronomSignatureVersion="125">Museum Digital File Descriptor</Generator>
  <DescriptionCreated label="Дата создания описания"
      iso="2026-09-17T16:55:24+03:00">17.09.2026 16:55:24 (UTC+03:00)</DescriptionCreated>
  <Item label="Сведения о предмете">
    <AccessionNumber label="Учётный номер (КП)">ГМИГ КП ЭФ-55</AccessionNumber>
    <Museum label="Музей">…</Museum>
    <Classifier label="Классификатор">Петров А.А._Соловки</Classifier>
    <Title label="Наименование">…</Title>
    <Description label="Описание">…</Description>
    <Topography label="Место хранения (топография)">…</Topography>
    <Carrier label="Носитель">…</Carrier>
    <Normalization label="Сведения о нормализации">…</Normalization>
    <FolderName label="Папка предмета">ГМИГ КП ЭФ-55_Петров А.А._Соловки</FolderName>
  </Item>
  <Files label="Файлы мастер-копии" count="1">
    <File n="1">
      <FileName label="Имя файла мастер-копии">ГМИГ КП ЭФ-55.mp4</FileName>
      <RelativePath label="Путь в папке предмета">video/ГМИГ КП ЭФ-55.mp4</RelativePath>
      <Format label="Формат" extension="mp4" mime="video/mp4">MPEG-4</Format>
      <FormatRegistry label="Формат в реестре PRONOM" registry="PRONOM" puid="fmt/199"
          url="https://www.nationalarchives.gov.uk/PRONOM/fmt/199">MPEG-4 Media File</FormatRegistry>
      <Category label="Вид файла" code="video">Видео</Category>
      <Size label="Размер" bytes="3545994">3,38 МБ (3 545 994 байт)</Size>
      <DateCreated label="Дата создания" iso="…">05.10.2022 14:03:59 (UTC+03:00)</DateCreated>
      <DateModified label="Дата последнего изменения" iso="…">…</DateModified>
      <ContentDate label="Дата создания содержимого (по метаданным файла)">…</ContentDate>
      <Checksums label="Контрольные суммы">
        <Checksum label="SHA-1" algorithm="SHA1">…</Checksum>
        <Checksum label="ГОСТ 34.11-2018 (ГОСТ Р 34.11-2012, «Стрибог», 256 бит)"
                  algorithm="GOST34.11-2018-256">…</Checksum>
      </Checksums>
      <Properties label="Технические характеристики">
        <Property label="Продолжительность" key="duration" raw="3723456.0">01:02:03.456</Property>
        …
      </Properties>
      <Tracks label="Дорожки">
        <Track label="Видеодорожка 1" type="video">
          <Property label="Кодек" key="codec" raw="AVC">AVC/H.264, профиль High@L4.1</Property>
          …
        </Track>
      </Tracks>
      <Preservation label="Замечания о пригодности для длительного хранения">
        <Note>Сжатие с потерями (видео): …(п. 33.10).</Note>
      </Preservation>
      <Warnings label="Предупреждения программы">…</Warnings>
    </File>
  </Files>
</DigitalMuseumItem>
```

### Элементы

| Элемент | Содержание |
|---|---|
| `DigitalMuseumItem/@formatVersion` | версия формата описания (сейчас `2.0`) |
| `Generator` | программа, её версия (`@version`), реализация хеша ГОСТ (`@hashBackend`), версия справочника PRONOM |
| `DescriptionCreated` | когда создано описание |
| `Item/AccessionNumber` | учётный номер (КП НВ / КП ЭФ) — есть всегда |
| `Item/*` | прочие сведения о предмете, если заполнены |
| `File/@n` | порядковый номер файла в предмете |
| `FileName`, `RelativePath` | имя файла; путь внутри папки предмета — только если файл лежит в подпапке |
| `Format` | название формата; `@extension` — расширение без точки |
| `FormatRegistry` | идентификатор формата в реестре PRONOM и ссылка на него (п. 33.13). Указывается только когда его можно выбрать однозначно по расширению и заголовку файла (версия PDF и PDF/A, JFIF/EXIF, GIF 87a/89a и т. д.) |
| `Category/@code` | `video`, `audio`, `image`, `text`, `other` |
| `Size/@bytes` | точный размер в байтах; текст — по образцу внутримузейных правил |
| `DateCreated` | дата создания файла. Если файловая система хранит и дату создания, и дату изменения, берётся **более ранняя**: при копировании Windows ставит «дату создания» на момент копии |
| `DateModified` | дата последнего изменения файла |
| `ContentDate` | дата из метаданных содержимого (EXIF, дата записи видео, свойства документа), если есть |
| `Checksum/@algorithm` | `SHA1` или `GOST34.11-2018-256`; значение — шестнадцатеричное, прописными буквами. SHA-1 идёт первой: так контрольную сумму считает КАМИС, и значения можно сравнивать с учётной базой. При сверке также распознаются `SHA256` и `MD5` |
| `Property/@key` | машинное имя свойства; `@raw` — значение без форматирования (число, код) |
| `Preservation/Note` | замечания по п. 33.10: сжатие с потерями, закрытый формат, DRM/пароль, не PDF/A |
| `Warnings/Warning` | что программе не удалось определить |

### Свойства (`Property/@key`) по видам файлов

* **Видео:** `duration`, `resolution`, `video_bit_rate`, `video_codec`,
  `frame_rate`, `container`, `overall_bit_rate`, `encoded_date`, `recorded_date`;
  в `Track` видео — `codec`, `resolution`, `display_aspect_ratio`, `bit_rate`,
  `bit_rate_mode`, `frame_rate`, `frame_rate_mode`, `scan_type`, `bit_depth`,
  `chroma_subsampling`, `color_space`, `compression_mode`, `language`;
  в `Track` аудио — `codec`, `bit_rate`, `channels`, `channel_positions`,
  `sampling_rate`, `bit_depth`, `compression_mode`, `language`.
* **Аудио:** `duration`, `container`, `overall_bit_rate` и дорожки, как у видео.
* **Изображение:** `compression` (с потерями / без потерь / без сжатия + метод),
  `pixel_size`, `resolution` (точек на дюйм), `print_size`, `color_mode`,
  `bit_depth`, `icc_profile`, `frames`, `camera`, `exif_date`.
* **Текст:** `encoding`, `language`, `characters` (знаков с пробелами и без),
  `words`, `lines`, `pages`, `slides`, `sheets`, `pdf_version`, `pdfa`,
  `text_layer`, `application`, `doc_created`.

Битрейт записывается в Мбит/с, для небольших значений — ещё и в кбит/с;
точное значение в бит/с — в `@raw`.

## Файл контрольных сумм

Текст UTF-8. Строки с `#` — пояснения. Остальные строки — в распространённом
формате BSD: `АЛГОРИТМ (путь) = значение`. Пути — относительно папки, где
лежит файл, разделитель `/`.

```
# Контрольные суммы цифрового музейного предмета
# Формат файла: 2.0. Создан: 17.09.2026 16:55:24 (UTC+03:00), Museum Digital File Descriptor 2.0.0.
# Предмет: ГМИГ КП ЭФ-55 (папка «ГМИГ КП ЭФ-55_Петров А.А._Соловки»).
# Строки: АЛГОРИТМ (путь к файлу относительно этой папки) = контрольная сумма.
# SHA1 — SHA-1; GOST34.11-2018-256 — ГОСТ 34.11-2018 (ГОСТ Р 34.11-2012, «Стрибог», 256 бит)

# Мастер-копия: ГМИГ КП ЭФ-55.mp4, 3,38 МБ (3 545 994 байт)
SHA1 (ГМИГ КП ЭФ-55.mp4) = 3F1A…
GOST34.11-2018-256 (ГМИГ КП ЭФ-55.mp4) = A8D1…

# Файл метаданных: ГМИГ КП ЭФ-55_Петров А.А._Соловки.xml
SHA1 (ГМИГ КП ЭФ-55_Петров А.А._Соловки.xml) = 7C02…
GOST34.11-2018-256 (ГМИГ КП ЭФ-55_Петров А.А._Соловки.xml) = 2D30…
```

Строки SHA1 можно проверить и без программы:

```bash
grep '^SHA1 ' "ГМИГ КП ЭФ-55_Петров А.А._Соловки.checksums.txt" | shasum -a 1 -c
```

Хеш ГОСТ выводится в том же порядке байтов, что у pystribog (версия 1.x),
gostcrypto и OpenSSL gost-engine: для контрольного примера M1 из стандарта —
`9d151eef…e57b5500`.

## Соответствие разделу XXXIII Единых правил

| Пункт | Требование | Как выполнено |
|---|---|---|
| 33.5, 33.7 | проверка технического состояния: считывание, сравнение с резервной копией, контрольные суммы | вкладка «Сверка» / `mdfd verify`: каждый файл читается целиком, суммы сравниваются с записанными, копия проверяется по суммам мастер-копии |
| 33.8 | проверка воспроизводимости | программа проверяет, что изображения, PDF и документы открываются, у видео и аудио — структуру контейнера. Воспроизведение проверяется плеером |
| 33.10 | открытые форматы без потерь и DRM | замечания `Preservation/Note` в описании и памятке |
| 33.11 | мастер-копия из одного или нескольких файлов | предмет — папка, `Files/File` на каждый файл |
| 33.12 | контрольные суммы мастер-копии | SHA-1 и ГОСТ 34.11-2018 (алгоритм правила не задают) |
| 33.13 | административные метаданные: форматы, идентификатор, суммы, ссылки на реестры, исходные форматы, инструменты нормализации | `Format`, `FormatRegistry` (PRONOM), `AccessionNumber`, `Checksums`, `Normalization`, технические свойства |
| 33.14 | описательные метаданные: идентификатор, суммы, данные книги поступлений | `Item` (номер, наименование, описание, топография, носитель) и `Checksums` |
| 33.15 | суммы мастер-копии и метаданных в текстовом файле вместе с именами | `<основа>.checksums.txt` |
| 33.16 | единица хранения в отдельном каталоге | папка предмета |

Отступления, о которых нужно знать:

* административные и описательные метаданные записываются **в один XML**
  (правила называют два файла). Решение принято сознательно: все сведения
  описаны в одном файле. Разделить их можно позже, не меняя остального;
* контейнер BagIt (рекомендация п. 33.16) не используется: файлы остаются на
  своих местах, а манифест — файл `.checksums.txt`.

## Изменения по сравнению с версией 1.x

| Было (1.x) | Стало (2.0) | Зачем |
|---|---|---|
| Корневой элемент `GMIG` (название музея) | `DigitalMuseumItem` с атрибутом `formatVersion` | формат не привязан к одному музею; версия формата видна в файле |
| Версии программы в XML нет | элемент `Generator` с версией программы | понятно, чем создано описание |
| Тег `Сommon` с кириллической «С» | тега нет, общие сведения — прямо в `File` | тег нельзя было найти поиском по `Common` |
| Подписи в атрибуте `name` | подписи в атрибуте `label`, машинные имена свойств — в `key` | `name` путался с именами файлов |
| Один файл мастер-копии на описание | `Files/File` — один или несколько файлов, в том числе из подпапок | сложносоставные предметы (п. 33.11) |
| Учётного номера нет | `Item/AccessionNumber` и другие сведения о предмете | идентификатор предмета и данные книги поступлений — пп. 33.13–33.14 |
| Тип хеша `GR3411_2012_256` | `GOST34.11-2018-256` | название по действующему стандарту; алгоритм тот же, значения совпадают с 1.x. SHA-1 оставлен, потому что его использует КАМИС |
| Дата изменения файла в UTC | дата создания и дата изменения, местное время со смещением, плюс ISO 8601 в `@iso` | дата создания нужна по перечню внутримузейных правил |
| Размер `3.38 MB (3 545 994 bytes)` | `3,38 МБ (3 545 994 байт)` + точный `@bytes` | образец внутримузейных правил |
| Необработанные поля MediaInfo (`format_url`, `other_…`) | отобранные свойства с русскими подписями | описание читается человеком |
| Нет ссылок на реестры форматов | `FormatRegistry` (PRONOM) | рекомендация п. 33.13 |
| Нет оценки формата | `Preservation/Note` | рекомендации п. 33.10 |
| Файл сумм `имя.txt` (затирал исходный `.txt`!) | `основа.checksums.txt` | см. обзор кода 1.x |
| Памятка `имя_KAMIS.txt` | `основа.kamis.txt`, можно отключить | единый вид имён |
| Ошибка хеширования записывалась в XML вместо суммы | описание не создаётся, предмет помечается ошибкой | в учётные данные не попадает мусор |

Описания версии 1.x программа распознаёт: не принимает их за мастер-копии и
проверяет при сверке (алгоритмы ГОСТ и SHA-1).
